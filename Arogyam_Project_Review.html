1. Executive Summary

Arogyam is a mobile-first personal health companion designed to help people organise everyday care. It brings medicine reminders, a simple health dashboard, Bluetooth health-band connectivity, emergency contact actions, and AI-assisted general guidance into one accessible interface.

The project is built with React, TypeScript, and Vite, with Capacitor support for Android and iOS and a Progressive Web App for browser access. The current version stores profile and medicine information on the device. A cloud database and account-based synchronisation are planned so a user can sign in and access their information after changing devices. This database is not yet implemented.

The project focuses on practical daily support: making it easier to remember medicines, record basic health information, and reach a nominated contact when help is needed.

2. Problem Statement

People managing routine medicines and health information may face practical challenges that are not solved by a reminder alone. Arogyam is designed around the following needs:

💊

Missed or Delayed Medicines

Busy routines, multiple medicines, and memory difficulties can lead to missed or late doses. A reminder with a clear medicine name, dosage, and time can support a more consistent routine.

👵

Difficulty Using Complex Apps

Some older adults find dense screens and multi-step tasks difficult. A clear home screen and a one-tap “Taken” action can make it simpler to record a dose after taking it.

🏠

Older Adults Home Alone

Family members may be at work while a senior family member is at home without immediate in-person support. Reminders and a quick emergency contact action provide useful support, while not replacing a caregiver or emergency service.

📋

Health Information in Different Places

Medicine schedules, personal health details, and daily readings can be difficult to keep organised when recorded separately or on paper. A single app can bring these routine details together.

🚨

Delay in Reaching a Trusted Contact

During a stressful moment, locating and dialling a family contact may take extra steps. Arogyam keeps a nominated contact and emergency call options available in the app.

3. Project Objectives

  1. Provide a daily medicine reminder system with native OS-level push notifications that work even when the phone is locked or the app is closed.
  2. Track key health vitals — heart rate, blood pressure, temperature, steps, and water intake — with real hardware band integration via Bluetooth Web API.
  3. Offer an AI health companion (Arogyam AI) for personalised, safe, non-diagnostic health guidance in both English and Hindi.
  4. Include a one-tap Emergency SOS system that surfaces the user's emergency nominee details instantly.
  5. Support bilingual interface (English + Hindi) with instant language toggle for accessibility across India.
  6. Protect personal information in the current local-storage version, and plan a secure, consent-based database with account sign-in and synchronisation for future access across devices.

6. Medicine Alarm System — Technical Deep Dive

The alarm system is the core innovation of Arogyam. It was engineered to work reliably across the Android WebView environment, which has stricter restrictions than a desktop browser.

Three-Layer Alarm Architecture

LayerTechnologyUse Case
Layer 1 — Native OS @capacitor/local-notifications Fires when app is closed, locked screen, or any other app is open. Daily repeating. Heads-up popup.
Layer 2 — In-App Timer setInterval (1-second tick) Fires the full-screen alarm card when user is actively using the app. Prevents duplicate fires using unique fireKey per medicine per day per time.
Layer 3 — Audio Web Audio API + HTML5 Audio WAV fallback Pleasant 4-note C5→E5→G5→C6 chime. Repeats every 1.6 seconds. Works in Android WebView with setMediaPlaybackRequiresUserGesture(false) in MainActivity.

Android-Specific Fixes

  • WebView Audio Unlock: WebSettings.setMediaPlaybackRequiresUserGesture(false) set in MainActivity.java — without this, Android silently blocks all timer-triggered audio.
  • Exact Alarm Permissions: SCHEDULE_EXACT_ALARM and USE_EXACT_ALARM added to AndroidManifest.xml so notifications fire at precisely the set time.
  • WAV Chime Generator: A PCM WAV file is generated programmatically in JavaScript (no external file needed) and played via HTML5 Audio as fallback if Web Audio API is blocked.
  • Multi-event Unlock: AudioContext resumed on pointerdown, touchstart, touchend, click, and keydown events — covers all interaction scenarios including Android's touch events.

7. Data Privacy, Storage & Security

Privacy and cross-device access are both project requirements. The current build stores the profile and medicine list in browser localStorage on the device in use. This means the information does not automatically follow a user to a new phone. The planned database will address that limitation.

📱

Current Local Storage

Profile, medicine schedule, and language preference are kept in localStorage on the current device. The current app has no account-based cloud synchronisation.

☁️

Planned Database

A future database will support authenticated access and synchronisation so users can retrieve their saved information after changing devices. This feature remains to be designed and implemented.

🛡️

Planned Privacy Controls

Database work should include user consent, secure sign-in, access controls, protected data transfer and storage, and a way for users to review or delete their records.

🤖

AI Data Handling

When the AI assistant is used, the app sends the message, selected profile fields, and current readings to the configured Supabase Edge Function for an AI response. The nominee phone details are not included in that AI payload.

Privacy statement: Arogyam aims to collect only information needed for its care features. Moving to cloud storage changes the privacy model and must be accompanied by clear notice, appropriate safeguards, and user control.

8. UI / UX Design Philosophy

Arogyam's design is guided by three principles:

1. Trust Through Calm Design

The color palette uses forest green (#2E8B57), lime (#C5CB3E), warm cream (#F8FDF9), and orange (#F0A020) — natural, calming tones associated with health and nature in Indian culture. Purple and violet are deliberately avoided. The typeface is clean and generous in size.

2. Simplicity for All Ages

The bottom navigation uses large icons with text labels. Every action needs at most one tap. The onboarding wizard breaks the setup into 12 small, friendly questions — never overwhelming the user. A "Skip for now" option is always available.

3. No Fake Data

Unlike many health apps that pre-fill demo vitals (like a fake heart rate of 72 BPM), Arogyam shows all health metric cards at zero until a real reading arrives. This builds trust with the user — what they see is real.

9. Challenges & Solutions

ChallengeSolution
Android WebView audio blocked by OS gesture lock Disabled setMediaPlaybackRequiresUserGesture in MainActivity.java. Added a programmatically-generated WAV chime as HTML5 Audio fallback. AudioContext resumed on all touch/click events.
Notifications not firing when app was closed Replaced web-only Notification API (which only works when app is open) with @capacitor/local-notifications — the native OS alarm scheduling layer used by real alarm apps.
Notification permission hanging on Android WebView Wrapped Notification.requestPermission() in a 500 ms timeout race so the UI never freezes waiting for a permission dialog that Android WebView doesn't show.
Hindi translation coverage for 200+ dynamic strings Built a custom two-tier i18n system: structured key-value translations for navigation/titles, and a flat lookup map (ui()) for inline dynamic strings like medicine food instructions and alarm messages.
Balancing local privacy and continuity across devices The current build keeps profile and medicine data in localStorage. A future authenticated database and synchronisation flow is planned to make user-approved records available on a new device.
Duplicate alarm triggers across days Implemented a composite fireKey = medicineId-YYYY-MM-DD-HH:MM lookup in a React state map. Resets at midnight when date changes. Prevents the same alarm from firing twice in the same minute.

11. Conclusion

Arogyam brings several everyday health-support features into a single mobile-first app: medicine scheduling and reminders, a one-tap medicine completion action on the in-app home screen, health information cards, optional Bluetooth band connectivity, an emergency nominee call action, and general AI-assisted guidance.

The design recognises that older adults may be at home without a family member present during the day. Clear reminders and fast access to a saved contact can help, while the app remains a support tool and cannot replace supervision, medical advice, or emergency services.

The current project stores profile and medicine data locally. Its next major development step is a secure, consent-based database and account system that allows users to access their information on a replacement or additional device. This planned feature is not yet available in the submitted build.

Arogyam aims to make routine health management clearer, more accessible, and easier to keep organised.
